# 短简介成对评测 v1

冻结日期：2026-10-18。仅用于离线评测，不替换运行时问题。

`profiles.jsonl` 是新写的 80 条合成资料，中英文各 40 条，各含 15 条五项全阴性的资料与 25 条至少一项阳性的资料。五项分别标注，允许重叠：每种语言推广阳性 20 条，诈骗、色情、角色声明、广告排版各 5 条。中英文有对应场景，不是 80 个独立随机抽取的真实用户。

**独立标注的含义**：本任务先依据下列规则逐条写下 `labels` 和 `why`，在任何本轮 Laya 推理之前冻结文件哈希；不使用 Laya 分数生成、修正标签。由助手完成标注，未经过第二位人工标注者审核。样本、标签和候选问法在本轮看结果后都不修改；此集只评测，不用于训练或调阈值。

## 标注规则

- `promotion`：昵称、用户名或简介主动推广与群主题无关的商品、服务、频道、群或招揽。普通职业／爱好、同群主题项目或课程介绍为阴性。
- `scam`：按现有 TAdmin 定义，收益保证、赌博、资金跑分、先付费领取空投，以及承兑／OTC／代付服务推广为阳性；只是金融职业、兴趣或反诈提醒为阴性。这里是策略信号，不是认定某个真实用户违法。
- `adult`：推广色情内容、裸照订阅或性服务；性健康教育、关系状态为阴性。
- `impersonation`：明确声称管理、版主、客服或官方身份。只判断声明，资料本身无法证明真假；姓名相似或否认管理身份为阴性。
- `ad_formatting`：服务／商品关键词列表、密集符号、重复交易号召等广告排版。一个装饰表情或普通一句话广告为阴性；该信号不等于另四类内容风险。

所有样本均给出简短标注依据。没有不确定标签；若后续人工审核有分歧，另建版本，不能覆盖本次冻结集。

## Telegram 长度与字段

账号简介使用 Telegram 官方配置的默认上限 70（普通）／140（Premium），不是消息正文上限。昵称／姓各不超过 64 字符；用户名为空或保守的 5–32 位字母数字下划线形式。本轮主要是短昵称和一句话简介，包含空简介、风险仅在昵称、职业／爱好、否定句、同主题推广和少量较长个人介绍。

`premium` 仅决定样本长度检查，不发送给模型。简介同时满足字符长度和更保守的 UTF-16 单元长度上限；不把 UTF-16 单元计数宣称为 Telegram 所有资料字段的统一服务端算法。边界测试覆盖 70/71、140/141、64/65 及 emoji；自然样本不为凑边界强行填充。

未指定的姓、用户名、群描述为空；群主题默认中文“Go 编程交流”或英文“Go programming”。只有账号四个文本字段和群标题／描述进入模型；ID、语言标签、Premium 标记、标注和解释均不发送。没有消息正文，本次不增加 4096 字符消息评测或群消息审核。

依据：[Telegram 客户端配置及简介默认限制](https://core.telegram.org/api/config)、[账号名称 API](https://core.telegram.org/bots/api#setbusinessaccountname)、[消息正文 API](https://core.telegram.org/bots/api#sendmessage)。配置参数可能动态变化；本轮以已记录的 70/140 保守范围构建。
