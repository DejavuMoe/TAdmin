# 验证流程

新成员入群后，TAdmin 会先把他**禁言**，再出一道只有他能回答的题；答对即恢复发言，答错或超时则移出。整个过程对其他群友几乎不可见。

## 一次典型的入群

1. **Alice 加入群组。** TAdmin 收到 `chat_member` 更新，先把这次验证写进数据库，再立即禁言。禁言自带到期时间（截止时间 + 10 分钟），即使机器人宕机，Alice 也不会被永远禁言。
2. **出题。** 群里出现一行欢迎提示，题目以“仅 Alice 可见”的临时消息弹出。
3. **作答。** Alice 按提示依次点击三个格子；答错会换一张新图，但截止时间不变。
4. **收尾。** 答对：恢复发言（若她入群前被管理员限制过，则原样恢复那份限制），删除提示与题目，按设置发送欢迎语。失败或超时：移出，并按递增冷却暂时阻止重新加入。

入群前后发生的一切都有持久化记录，重启会从断点继续，详见 [入群状态机](/design/state-machine)。

## 谁不需要验证

| 情况 | 原因 |
|---|---|
| 所有者、群管理员 | 已受信任 |
| 由管理员拉进群的人 | 管理员已为他担保 |
| 使用名称含 `#免验证` / `#noverify` / `#trusted` 的邀请链接入群 | 管理员创建的受信链接，适合线下活动、朋友邀请 |
| 通过入群申请进入 | 批准前已经验证过（或由管理员人工批准） |
| 验证途中被升为管理员 | 流程自动取消并解除禁言 |

::: details 入群服务消息与 chat_member 更新的先后
Telegram 会同时发送“X 加入了群组”服务消息和携带邀请链接等细节的 `chat_member` 更新，两者到达顺序不固定。TAdmin 以后者为准：若服务消息先到并开始了验证，而随后的更新显示此人应当豁免，会立即撤销并解除禁言；反之亦然。
:::

## 失败、超时与冷却

- 默认 **180 秒**、**3 次机会**，都可以在控制台调整。
- 答错换新题，**不延长**截止时间；旧题上的点击只会刷新画面，不计次数。
- 次数用尽或超时：**移出**，封禁到期自动解除。24 小时内反复失败，冷却按 ×4 递增：

- 也可以把“次数用尽”设为 **转人工**：成员继续保持禁言，管理员在群里的审核卡上决定。

## 人工审核

以下情况会进入人工审核：新人点击 **🆘 需要帮助**、次数用尽且设置为转人工、AI 判定资料高风险（答对后仍需确认）、题目因机器人权限问题无法发出。

- 直接入群：群里的欢迎提示就地变成审核卡 **[✅ 放行] [🚫 移除] [⛔ 封禁]**，本群管理员都能操作，非管理员点击会被拒绝。
- 入群申请：审核卡私聊所有者。
- 审核期间禁言会延长到审核窗口结束（默认 15 分钟）。到期无人处理时默认移出；但如果是**题目无法投递**，到期会放行——不因机器人的故障惩罚用户。

## 入群申请与 Guard

群开启“需要审批才能加入”后，申请者会在私聊收到题目，答对自动批准。验证完成前他根本不在群里，**没有任何可发言的窗口**。

- Telegram 只允许机器人在申请后 **5 分钟内**私聊申请者，所以此模式的时限最长 4 分 30 秒。
- 无法私聊申请者（例如对方关闭了私聊）时，申请转给所有者人工审核。
- 如果群把 TAdmin 指派为 **Guard 机器人**（Bot API 10.1）且配置了 Mini App，申请时会在 10 秒内直接弹出验证页；Guard 查询过期后，结果会自动改用普通的批准 / 拒绝接口完成。
- 有未完成申请的人如果改用其他链接直接入群，申请流程会被取消，改为按直接入群验证。

## 能力边界

::: warning 验证码不是万能的
- 从成员进群到禁言生效之间有网络延迟（通常不到一秒）。这段时间里发出的消息会被自动删除，但不能保证“连一条都发不出来”。若要求绝对零窗口，请使用入群申请模式。
- 验证码能显著抬高批量自动入群的成本，但挡不住真人广告号或专门训练的识别脚本。
- 通过验证只说明“入群时是个会点按钮的人”，不代表以后不会发广告——而 TAdmin 刻意不做发言审查。
:::
