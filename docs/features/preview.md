# 链接预览刷新

Telegram 会缓存网页的链接预览。TAdmin 通过可选的用户号向 **@WebpageBot** 提交链接刷新请求，按其回复显示结果；这不等于独立验证所有客户端都已显示新预览。建议使用专用小号，核心入群功能不依赖它。

## 两种用法

**手动刷新。** 把任意链接私聊发给机器人（或 `/refresh 链接`），点 **🔄 刷新预览**，结果当场回显：

> ✅ 预览已刷新（3.2 秒）
> ❔ 已提交，@WebpageBot 的回复无法识别
> 🚫 该链接没有可用的预览

一次发多个链接时，第一条立即刷新，其余进入队列。

**订阅自动刷新。** 添加一个网站，TAdmin 自动发现它的 sitemap 或 Feed，页面更新时自动排队刷新：

<Steps>

1. **添加来源** —— 发送网站首页、`sitemap.xml` 或 RSS / Atom / JSON Feed 地址。TAdmin 会查看 robots.txt 里的 `Sitemap:`、页面中的 `<link rel="alternate">` 以及常见路径，并逐个验证能否解析。
2. **选择起点** —— “🆕 只刷新之后的新文章 / 变更”，或“📥 把现有链接也全部刷新一遍”。
3. **周期检查** —— 默认每 6 小时检查一次；普通来源可用 ETag / Last-Modified 条件请求，sitemap 索引仍检查子来源（最深 3 层）。新条目与带更新时间的变更进入队列；基线失败或遍历不完整会报错，不悄悄当作成功订阅。
4. **慢速队列** —— 全局单通道、默认 45 秒 ± 抖动一条、每日上限 300 次、同一链接 24 小时内不重复，自动遵守 Telegram 的 FLOOD_WAIT。批次完成后只给你发一条摘要。

</Steps>

## 用户号登录

控制台 **🔄 预览刷新 → 👤 用户号**，全程在私聊中完成：

- **📷 扫码登录（推荐）**：机器人发来二维码，在要登录的账号手机上打开 **设置 → 设备 → 连接桌面设备** 扫描。二维码每 30 秒自动刷新。
- **📱 手机号登录**：发送手机号后，用**内联数字键盘**输入验证码。验证码不会以消息形式出现在聊天里——Telegram 会拒绝“被分享过”的验证码。
- **两步验证**：按提示发送密码，消息会在读取后立即删除。

会话只保存在你本地的 SQLite 中。

特殊邮件设置、词语验证码等 Telegram 登录分支尚无完整控制台支持，遇到这种情况改用扫码。超时或无法识别的回复按未知处理；没有回复绑定的消息只能按顺序归属，实群试用时需核对效果。

## 安全与礼貌

- 抓取器在**连接时**校验目标 IP，拒绝回环、内网、链路本地、CGNAT 等地址（可用 `preview.allow_private` 显式放开）。
- 响应体解压后上限 20 MiB；最多 5 次跳转；只接受 http / https。一次 sitemap 遍历最多尝试 1000 次获取，失败也计入预算；单个 JSON Feed 最多解码 50000 项。
- 最小间隔在任何情况下都不会被“唤醒”缩短；每日上限按实际发出的刷新次数计算，重新排队不会重置计数。

## 相关配置

```toml
[preview]
check_interval = "6h"   # 订阅源检查间隔（≥ 10m）
min_gap = "45s"         # 两次刷新的最小间隔（另加随机抖动，≥ 5s）
daily_limit = 300       # 每日最多刷新次数
allow_private = false   # 是否允许抓取内网地址
```
