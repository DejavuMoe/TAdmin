# Jev 与 Laya 短 noul v1：冻结 140 条资料基线

日期：2026-10-18。结论：**保留 Jev，停止对当前 Laya 多语言 checkpoint 继续做提示词微调；Laya 暂不作为可用替代。** 本轮只运行独立评测，没有启动机器人、替换运行时问题、改变仅提示模式或部署服务器。

## 实际调用与公平对照

后续已完成 [Jev 当前运行时原问题与短 v1 的对照](./jev-runtime-comparison)：同一冻结 140 条资料支持保留原问题，没有替换运行时问题。

- 按用户提供的本地代理 `http://127.0.0.1:3425/v1/systemone`，请求 `typesafe/jev-latest`。140 次响应全部返回 **`jev-1.13.0`**，每次五个有效 noul，未重试或挑选结果。请求别名可漂移；本次版本以实际响应为准。
- 原样使用 `diagnose.SHORT` 的短 noul v1、相同结构化 state 和冻结标签；没有使用 v2，也没有把运行时长问题用于这一轮 Jev。标签、理由、语言标记和 slice 不发送给模型。
- Laya 对照复用上轮 `laya-2026-10-18-profile-v2.json` 中的 **`short_noul`** 响应，不重新推理。模型为 `convaiinnovations/laya-multilingual`，revision `1720e3e3357cfe1e281542e223f8273b0890ca34`，原预算 2048/1024。逐条检查完整答案与无截断元数据。
- 两组共 140 条，中英文各 70；旧冻结集 80、新挑战集 60。样本、标签、原协议和脚本均通过已有冻结哈希校验；本次记录 Laya 结果文件与 Jev 执行脚本的 SHA256。
- 仍采用预先规定的 `p >= 0.5` 和 `p >= 0.85`，不调阈值。误报率为 FP/阴性数，漏报率为 FN/阳性数；每项分母不同，多标签资料可同时进入多个阳性集合。

[官方模型说明](https://docs.typesafe.ai/models)在本次查阅时将稳定别名映射到 1.13.0；[API 文档](https://docs.typesafe.ai/api)将 noul 定义为肯定答案的概率。Jev 请求只包含 model、state、questions，不发送 Laya 的专用预算参数。

## Jev 的两个主要风险错例与排版问题

- `en37`：昵称 `[ADS][VIEWS][FOLLOWERS]`、空简介。推广分数 **Jev 0.44，Laya 0.8568**；Jev 没有在 0.5 下识别这条昵称服务推广。
- `new-en25`：`Settlement desk`，简介 `Offering USDT over-the-counter exchange and proxy payments.`。金融风险 **Jev 0.49，Laya 0.9948**。标注将 OTC／代付按现有业务策略列为金融风险，而短问题询问诈骗／赌博，两者并非完全等价；不能直接把此例说成 Jev 不懂骗局。Jev 对该条的推广判断仍为阳性。
- 广告排版：冻结规则关注醒目符号、大写、联系方式堆叠等格式，但 v1 仅问“像不像广告”，也可能把普通句式的广告内容算入。例：`zh12` 的“出售 Go 入门课程，欢迎咨询。”排版分数 0.76，`zh16` 的“换屏换电池，私聊预约。”为 0.80。两模型都存在误报，提示题意与标注口径不充分对齐；本轮没有通过修改标签或改题消除错误。

## 是否继续用 Laya

当前证据支持停止对这个 Laya checkpoint 做小幅提示词迭代：相同短问题、相同输入下，Jev 在角色字段、反诈语义和频道推广上明显更可靠；差异不足以用“短问题本身完全不可用”解释。结合此前输入格式、token 预算与截断检查，问题更倾向于当前 Laya 模型及其推理实现对这些任务的适配能力，而不是 TAdmin 运行时请求代码。

这不是隔离模型权重与上游实现的实验，也不证明所有本地模型都不适用。保留现有可切换接入和评测证据即可；若以后有新 checkpoint，再跑冻结基线。现阶段继续保留 Jev 和仅提示策略，不把本轮 v1 离线成绩当成当前运行时长问题的验收，也不自动更换问题或阈值。
