# 安全模型

## 信任边界

| 输入 | 视为 | 如何处理 |
|---|---|---|
| 按钮的 `callback_data` | 完全不可信（任何人都能伪造） | 每次都重新读取流程与群，校验点击者身份与当前 Telegram 管理员权限；格式异常直接忽略 |
| Mini App 请求 | 不可信 | 服务端校验 `initData` 的 HMAC 与签发时间（1 小时内），要求 `user.id` 与流程绑定用户一致；Guard 流程还要求 query id 一致；每个流程每分钟最多 40 次请求 |
| 用户昵称、群名、链接 | 不可信文本 | 进入 HTML 消息前一律转义；欢迎语按钮只接受 http(s) / tg 链接 |
| 预览订阅源 | 不可信网络资源 | 连接时校验 IP、限制体积与跳转，拒绝内网地址 |
| AI 判断 | 参考意见 | 只能让流程更严格，不能放行或封禁 |

## 授权

- 所有者由配置决定；群管理员以 Telegram 为准（10 分钟缓存，成员变更即时失效）。
- 非所有者拉入的群处于“待授权”，对非所有者完全不可见、不可操作——包括通过深链、面板按钮、暂停按钮等任何途径。
- 群管理员只能操作自己所在的群；需要“封禁用户”权限，置顶相关操作还需“置顶消息”权限。机器人不会放大任何人的权限。
- 匿名管理员无法确认身份，所有管理操作都会被拒绝。

## 验证码

- 答案不写入数据库、不下发给客户端；只保存随机种子与代数。
- 每个流程绑定 128 位以上的随机令牌；深链与 Mini App 地址只含令牌，打开别人的令牌会被拒绝。
- 所有状态转换都在按流程加锁的情况下进行，同一答案不能被提交两次。

## 秘密

- Bot Token 只来自环境变量或文件；所有错误信息在输出前都会把 Token 替换为 `<token>`。
- 日志不记录 initData、答案、手机号、登录验证码、两步验证密码或会话数据。
- 用户号的手机号、密码消息在读取后立即从聊天中删除；登录验证码用内联键盘输入，从不以消息形式出现。
- 数据库文件权限为 `0600`；备份包含用户号会话，需妥善保管。

## HTTP

- 默认只监听 `127.0.0.1`，由反向代理提供 HTTPS 与按客户端限流。
- 严格的 CSP（只允许自身脚本与 telegram.org 的 SDK、不允许内联样式属性）、`nosniff`、`no-referrer`；请求体上限 32 KB，验证图并发渲染上限 4。

## 已知局限

- 直接入群到禁言生效之间存在短暂窗口（通常不到一秒），期间的消息会被删除，但无法保证零窗口；需要零窗口请使用入群申请。
- 图形验证码可以被专门训练的视觉模型破解；它的目标是抬高批量成本，而不是“不可能”。
